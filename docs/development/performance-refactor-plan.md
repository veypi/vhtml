# vhtml 通用性能重构方案

2026-09-16 · R0–R3 已实施。基于 vhtml 0.11.0、已完成的 V1–V4，以及 aic 首次分页、虚拟列表和资源释放的实际回归。

第一轮核心重构已交付源码、生产构建和回归用例，结果见 [R0–R3 实施报告](./performance-refactor-results.md)。R4 保持后续独立交付，R5 保持条件项。下文保留设计依据与验收契约。

## 目标与边界

让框架统一保证三件事：同一数据保持稳定身份，列表变更保留仍然存在的组件，组件退出后释放其订阅和排队任务。通用列表工具负责限制挂载规模，应用继续决定哪些数据需要显示和保留。

普通组件模板、`v-for`、`v-if`、props、slots、路由及生命周期保持现有用法。此次重构不增加搜索、长正文分页或其他产品交互，不根据业务对象的 `id` 自动合并实体，不默认将普通列表虚拟化。

已完成的 V1–V4 继续作为基础，不重复重写：

| 已完成 | 保留的能力 |
| --- | --- |
| V1 | effect 双向依赖、过期依赖解绑、Cancel 释放引用 |
| V2 | DOM 移除候选合批、祖先去重、显式 dispose 与外部移除兜底 |
| V3 | 共享模板规范化、注释剔除、显式空白压缩 |
| V4 | 文本/class/style 按实际变化写入 DOM |

详见 [V1–V4 实现与验证](./performance.md)。以下使用 R0–R5 编号，避免与前轮计划中的待评估 V5 混淆。

## 已确认的问题与证据

| 现象 | 当前代码 / 实测 | 结论 |
| --- | --- | --- |
| 同一原始对象重新进入数组，旧列表行重建 | `src/reactive.js` 的 `Wrap()` 每次创建代理与 DataID；最小复现中，前插后原行 DOM 身份不相等 | 普通数据的代理身份缺少统一缓存 |
| 两个属性引用同一个对象，通知分离 | `Wrap({a: shared, b: shared})`；先订阅 `a.n`，经 `b.n` 写入后，`a.n` 已变化但 watcher 保留旧结果 | 字段通知应按原始目标共享 |
| aic 首次翻页时消息重新展开 | 显示行缓存保存 raw，框架把投影数组条目换成 proxy；下一次投影再次交出 raw，触发重新包装 | 应由框架保护普通数据身份，应用仍须保留实体引用 |
| 暖列表流畅，首次分页不流畅 | 首次有请求延迟、异步组件挂载、未测高度和临时分区头；原测试主要覆盖已加载列表 | 冷首次交互必须进入通用浏览器回归 |
| 仅删除节点不等于完成资源释放 | scope 已托管 watcher、监听器和 timer；组件仍手动管理 rAF、observer | 沿现有 scope 补齐资源入口即可，无需另一套生命周期 |

最小复现的关键输入是“同一个 raw 引用”，不是两个内容相同的新对象。`raw.n = value` 直接写原始对象仍然不会经过 Proxy；本方案不改变这一约束。

## 实施顺序

| 阶段 | 内容 | 优先级 | 交付判断 |
| --- | --- | --- | --- |
| R0 | 固定基线与回归场景 | 必做 | 记录现状，新增失败用例能复现问题 |
| R1 | 代理身份、共享通知与作用域隔离 | 第一批 | 两个最小复现通过，旧数据/作用域语义无回归 |
| R2 | 列表复用契约与等价更新快路径 | 第一批，依赖 R1 | 前插只新建新增行；相同列表不重复处理行 |
| R3 | scope 资源托管补齐 | 第二批 | 自然完成和销毁均释放排队资源 |
| R4 | 可选的通用虚拟列表工具 | 后续独立交付 | 应用接入后行为和首滚指标保持 |
| R5 | 统一布局后置调度 | 条件项 | 仅在 R1–R4 后仍测得重复测量热点时实施 |

核心重构的第一轮完成范围为 R0–R3。R4 作为独立工具验收；R5 不阻塞核心交付。每阶段单独审阅、记录指标，上一阶段通过后再进入下一阶段。

## R0：建立能覆盖首次交互的基线

保留当前工作区的 V1–V4 和 aic 修复，实施前对当前源码、生产包及测试页做一致的基线快照。不能把 Git HEAD 自动当成“优化前”，因为当前已有未提交实现。

增加或扩展以下确定性场景：

- 同一 raw 经多条属性路径、多个数组和多个组件传递；分别读写并核对通知。
- 1,000 / 10,000 行列表：同值更新、前插、删除、重排、全量替换、函数源列表。
- 列表中包含输入框和有本地状态的子组件，核对焦点、选区和组件身份。
- 首次只加载 20 条尾部，随后 50 条分页；请求延迟分别为 120ms、500ms，包含变高正文及异步子组件。
- 同页 1 / 2 / 4 个视图；20 次挂载销毁；条件分支反复切换；路由缓存停用和恢复。

继续使用数字计数器。新增计数优先放入现有 `perfStats`：代理创建/命中、列表 reconcile/快路径、新建/移动/销毁行、待处理资源数。禁止为统计维护强引用对象或 DOM 的全局历史列表。

## R1：统一数据身份，隔离作用域上下文

主要文件：`src/reactive.js`。同步审计 `src/compiler.js`、`src/module.js`、`src/slots.js`、`src/component.js` 中的 `Wrap`、`EnsureWrap`、`SetDataRoot` 调用。

### 数据身份契约

- 同一运行时内，同一普通 raw 对象在仍存活期间取得同一 canonical proxy 和 DataID。
- `EnsureWrap(proxy)` 幂等；`Wrap(proxy)` 不再套第二层代理。
- 新 raw 对象仍是新实体，即使字段或业务 `id` 相同，也不与旧实体合并。
- 同一 raw 的自有字段依赖和通知共享；经任一代理写入都能通知所有相关订阅者。同一个 watcher 在一个 batch 中仍只进入一次 dirty 队列。
- 循环对象、自引用数组、嵌套共享对象走同一缓存，保留惰性包装。
- `__noproxy`、DOM、Date、RegExp、Event 等已有排除规则保持。

### 内部组织

采用按 raw 保存的弱元数据：`targetMeta: WeakMap<raw, TargetMeta>`。TargetMeta 管理自有字段通知通道、数组通道和普通数据的 canonical proxy。现有 `proxyMeta` 继续支持反查、描述符及内部身份操作。

普通数据代理不得隐式携带当前组件、父级或 DOM。缓存也不得附带可枚举的强引用镜像。原始对象被应用保留时，其代理可存活；应用与 watcher 均释放后，元数据必须可被 GC 回收。

### root 不能直接塞进共享缓存

当前 root 链还承担迭代变量、模块 globals、slot `vbind` 的词法查找与穿透写入。重构中把“共享数据目标”和“作用域上下文”分开：

- 框架创建的迭代/slot/模块作用域使用独立本地容器和作用域包装；root 保存在该包装的元数据中，不写入共享业务 raw。
- 普通数据按 raw 复用代理；作用域包装按其作用域身份保留，不跨父级自动复用。
- 有 root 的 `Wrap/EnsureWrap` 保留兼容入口，内部转到作用域包装路径；不能因 canonical 缓存命中而静默覆盖另一作用域的 root。
- `SetDataRoot` 保留显式重绑所传作用域包装的能力；已注册的继承读取需要失效并重新收集依赖，不能继续订阅旧 root。修改一个作用域的 root 不影响其他作用域。
- 自有字段通知归属 target；继承查找、root 重绑失效属于作用域包装。`defineProperty` 的显式本地写入、只读描述符、getter receiver 和赋值穿透语义保持。

内部可引入作用域包装辅助函数，但不增加模板指令，也不要求业务调用新的响应式 API。`DataID` 继续作为框架内部身份使用，不替换成业务主键。

### 验收

| 输入 | 必须满足 |
| --- | --- |
| raw 同时作为 `a`、`b` | 普通代理严格相等；经 b 写入能更新 a 的订阅 |
| `[raw]` 改为 `[newRaw, raw]` | 原行 DOM、子组件及焦点保留，仅新建一行 |
| 两个同形的新对象 | 仍是两个独立实体，互不污染 |
| 同一业务对象传入两个组件 | 字段通知共享，组件各自局部变量和父级查找独立 |
| 两个作用域及 slot root 重绑 | 本地遮蔽、穿透写入正确，不串 root，不残留旧依赖 |
| 撤销 watcher 后释放 raw/proxy | 独立 GC 实验中弱引用可清理，无额外 scope/DOM 保留 |

同步更新 `test/copybind.test.js` 中“数据共享、通知分离”的旧现状说明，扩展成别名通知契约。纯替换、数组搬移和函数源列表的原有行为仍需通过。

## R2：让列表更新成本与实际变化相称

主要文件：`src/compiler.js`、`src/reactive.js` 的 `mergeIntoProxy`，以及列表回归测试。

R1 首先解决错误重建。R2 在此基础上收紧 `v-for` 的复用和执行范围：

- canonical 对象行按稳定身份匹配；保留行只在相邻位置确实变化时移动 DOM。
- 前插、删除、排序不清空整个列表，不重建保留行的绑定、事件和组件。
- 建立等价快路径：条目数量、迭代 key、顺序、值/引用均与上次相同时，跳过 keep Set、逐行赋值及 DOM 调和。
- 快路径必须比较实际值。函数源产生的新对象即使位置、形状相同，也要继续执行现有位置合并；原始类型值变化、迭代 key 变化同样不能跳过。
- 对象身份匹配依据有效的响应式包装，不把 raw 上历史遗留的 DataID 印记当成新的身份凭据；函数源 raw 条目不能因读过一次就从位置匹配突然切到身份匹配。为该边界单独增加回归。
- 重复对象引用仍按现有重复条目规则处理，不能把两处 DOM 合并成一行。
- 保存的上轮顺序快照随结构指令销毁而清空；最多持有当前列表规模，不保存历史版本。

此阶段不承诺将数组结构更新降为 O(1)：数组收集和顺序比较仍可为 O(n)。确定性收益是消除不必要的代理创建、行重建、作用域重建与 DOM 移动。暂不引入增量数组补丁协议或新的 `:key` 语法。

验收包括：原节点严格相等、输入框焦点/选区保留、子组件 mount/dispose 次数准确；同一列表重交时行新建/移动/销毁均为 0；新对象替换和函数源位置合并仍符合原契约。

## R3：补齐组件退出时的资源回收

主要文件：`src/component-scope.js`、`src/lifecycle.js`；保留 `src/runtime-watch.js` 和 V2 的统一销毁路径。

现有 `$scope.addCleanup`、监听器和 timer 托管继续使用。优先增加 scope 所属的 rAF 注册/取消能力，并让 observer、外部订阅通过现有 cleanup 注册释放；无需再增加一套 observer 工厂或自动可见性探测系统。

资源必须同时处理两种结束方式：自然完成、组件销毁。rAF/timeout 回调自然完成时先退出 pending 集合，避免活着的组件积累已执行任务；取消和 dispose 均幂等，销毁后的迟到注册直接清理，已排队回调不得再触发用户代码。

`active/deactive` 用于组件明确管理的活跃期工作，`dispose` 才代表终止。框架不因任意 CSS 隐藏就自动暂停所有 watcher，也不冻结数据订阅。像头像这样可销毁的视图继续由外层 `v-if` 控制；需要保留状态的隐藏视图由宿主明确管理。

验收：自然执行 1,000 次短任务后 pending 回到 0；20 次挂载/销毁后 live watcher、依赖边、受托管资源回到预热基线；取消后不再调用业务回调；一个 cleanup 抛错不阻断其余清理；路由缓存停用不会被误销毁。

## R4：抽出可选的虚拟列表工具

来源：aic 的 `ui/ai/virtual-list.js`。交付形态为独立 ESM 工具入口，单独构建和导出，普通框架入口不自动创建控制器或监听器。具体文件/导出名在接入提交中固定，不新增 `v-virtual-for` 指令。

通用部分：

- 可变高度前缀索引、按像素定位行、宽度及内容版本对应的测量缓存。
- 可配置缓冲区和边界滞后；新旧窗口交集保持稳定行引用。
- 稳定行标识＋实际像素偏移的阅读锚点；行删除时选择仍存在的邻接锚点。
- 同一轮占位写入与滚动补偿；异步行高度不足时避免 scrollTop 被钳制；新挂载内容不能取代正在阅读的锚点。
- 外部明确传入可见性；隐藏时停用测量与待执行绘制，销毁时断开观察及节点引用。
- 键盘滚动、拖动滚动条、顶部/底部定位、宽度变化和文本选区保护。

通过 adapter 提供 `getId`、`estimateHeight`、`getVersion`、`canAnchor`、渲染和接近边界通知。工具中不再出现 `zone:`、消息角色、`_bodyUnloaded`、聊天状态或服务器请求。aic 自己决定分区投影、冷正文占位、预取阈值及底部跟随条件。

工具不缓存已卸载 DOM；仅保留当前挂载节点、有限任务、行引用和测量结果。测量缓存随行删除清理，destroy 后清空。数据及高度元信息仍随行数增长，不能宣传总内存与历史长度无关。

接入先保持 aic 已验证行为及接口适配，再删除被替代的实现，避免长期维护两套控制器。不改变普通页面的原生查找、文本选择或无障碍行为；选择接入虚拟列表的页面应明确其仅挂载局部 DOM 的既有边界，不用新增搜索或分页 UI 补偿。

验收使用固定数据/视口：1,000 与 10,000 行的挂载量由视口和缓冲决定；前插 120 次滚动中保留行重挂载为 0、固定字体下锚点额外位移 <1px；120ms/500ms 请求延迟下既定滚动速度不撞顶等待；恢复隐藏视图显示最新内容；反复开关后资源回基线。

## R5：布局后置调度，仅在实测需要时推进

若 R1–R4 后仍有多个组件在同一更新中重复测量，可在现有调度器加入按 scope 和任务 key 去重的后置任务队列：本轮响应式 DOM 更新完成后集中测量，再统一提交依赖测量的写入。scope 销毁时取消任务，异常隔离，级联预算保持有限。

它只保证“当前已完成的 DOM 更新”的执行顺序，不代表网络请求、异步子组件、图片或字体都已就绪；这些完成后需要再次失效和调度。不能用一个 nextTick 承诺所有布局稳定，也不能在未测量前删除必要的 ResizeObserver/MutationObserver 补偿。

没有明确的重复测量收益就暂不实施。编译分片、默认暂停隐藏视图、改变生命周期先后顺序也不进入本轮核心重构。

## 验证与交付门槛

每阶段先运行对应回归，再跑完整测试、构建及浏览器验证：

```sh
npm test
node --expose-gc scripts/check-reactive-gc.mjs
npm run build
```

扩展现有 `test/browser/performance.html`，分别验证源码和 `dist`。GC 脚本扩展代理缓存、取消任务及作用域释放场景；不能用单次 GC 时序作普通单测的唯一判断。

| 检查面 | 核心指标 |
| --- | --- |
| 正确性 | 数据值、跨别名通知、root 隔离、双向绑定、slots、描述符、生命周期 |
| 列表复用 | 前插新建数等于新增行；保留行无重挂载；等价更新无 DOM 移动 |
| 首次交互 | 冷/暖缓存、首次上滑、异步子组件、历史分页、连续变高内容 |
| 资源释放 | 活跃 watcher、依赖边、pending 任务、挂载节点回基线 |
| 性能 | 节点、代理创建、实际写入、调度与测量次数；固定环境多次采样耗时 |
| 兼容性 | 普通 v-for、函数源列表、v-if、vsrc、props、refs、slots、路由缓存与中止挂载 |
| 应用回归 | aic 1/2/4 窗口、首次翻页、展开/收起、流式、隐藏恢复、关闭重开 |

耗时至少采样 10 次并记录中位数和分位数，保留浏览器版本、视口和数据集。优先以确定性的工作量和身份断言决定通过，不以一次运行的毫秒差判定收益，不承诺浏览器总 JS 堆的固定 MB 上限。

每阶段文档记录改动前后结果，随后才更新 `dist`、CHANGELOG 和框架使用说明。核心代理/作用域语义变化按兼容性变更记录；本方案不自动确定版本号或发布 npm。

## aic 迁移与回退

R1/R2 验收完成后，在 aic 先保留已有显示行代理回存保护。框架源码和生产包都通过真实首次翻页测试后，再独立移除冗余保护；消息实体和显示行引用稳定性的业务责任仍然保留。

检查应用是否曾依赖“直接改 raw，再重新交出数组触发重挂载”刷新内容。此类写入改走响应式代理，或生成真正的新实体；重交同一实体不再承担补偿未通知写入的职责。函数源列表既有的位置合并行为则按 R2 的兼容契约保留。

R3 只迁移确有重复清理代码的组件。R4 接入以一个视图完成验证后再扩展，保持原消息展示和交互。头像的外层 `v-if` 策略保持。

回退按阶段源码和对应构建产物成对进行，恢复到实施前保存的工作区基线，不覆盖已有 V1–V4 或用户改动。R4 可回退到 aic 已验证的本地控制器；核心响应式系统不同时驻留两套实现，不增加长期运行时兼容开关。

建议第一轮实际开发顺序：R0 → R1 → R2 → R3。先把已证实的问题变成框架契约，再迁移可选工具。
