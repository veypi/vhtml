# 模块运行时与 unsafe 沙箱重构规划

日期：2026-10-01。状态：规划，尚未实施。本文描述目标结构，不代表当前版本已经具备这些隔离保证。

本次按发布前重构处理：旧入口直接删除，仓库内调用方一起修改，不提供兼容参数、旧实现回退、双写状态或长期并行的迁移层。已有组件生命周期、响应式和列表身份等有效契约保留；不为复刻旧实现的偶然行为增加分支。

## 1. 固定契约

后端声明模块身份和信任级别：

```http
vhtml-scoped: /modules/demo
vhtml-unsafe: 1
```

- `vhtml-scoped` 确定模块的真实挂载根；身份由规范化的 origin 和 scoped 共同组成。
- `vhtml-unsafe` 只在模块首次登记时读取，按存在性判断：有该头就是 unsafe，没有就是普通模块。第一次加载是什么就是什么，此后不再读取该模块响应中的 unsafe 标记。
- unsafe 必须有明确、有效的 scoped；缺失不能默认为整个站点根。代码请求与响应声明的模块归属必须校验。
- 元信息在任何模块代码执行前确定，保存在框架私有记录中。`$mod` 若公开 scoped/unsafe，只提供只读视图。
- unsafe 是模块初始化常量，不是运行时状态。后端负责标记的正确性；后续标记变化属于后端 bug，前端不检测、不告警、不切换执行器，也不因此失效或重建模块。
- 模板、模块配置和业务数据分开：普通 `vhtml-*` 配置不能覆盖身份、权限、执行器或框架能力。业务 API 响应不重新定义模块权限。

模块代码看到的是模块内地址空间：

| 输入 | 结果 |
| --- | --- |
| `fetch('/api/xxx')` | 请求 `/modules/demo/api/xxx` |
| `fetch('api/xxx')` | 请求 `/modules/demo/api/xxx` |
| `xhr.open('GET', '/api/xxx')` | 请求 `/modules/demo/api/xxx` |
| `new WebSocket('/api/socket')` | 使用模块 origin 对应的 ws/wss 协议，连接 `/modules/demo/api/socket` |
| `new EventSource('/api/events')` | 连接 `/modules/demo/api/events` |
| `navigator.sendBeacon('/api/report', data)` | 发送到 `/modules/demo/api/report` |
| `<img src="/assets/xx.png">` | 资源归属 `/modules/demo/assets/xx.png` |
| `import './helper.js'` | 相对当前 JS/组件文件解析，再检查模块边界 |
| `import '/lib/helper.js'` | 相对模块根解析 |
| `@/api/xxx` | unsafe 明确拒绝 |
| 规范化后越出模块根 | 明确拒绝，不截断到边界后继续 |
| 外部 URL、协议相对 URL | unsafe 默认拒绝 |

首版通过模块内后端接口提供获准的网络服务，不另造一套前端外域授权配置。普通模块可以保留全局资源访问能力；其路径解析也使用同一套实现。

## 2. 唯一模块记录与初始化流程

模块私有记录拥有元信息、资源服务、平台对象（platform）、执行器、模块数据、资源回收器和代次；组件只持有所属模块的引用，不再拥有 unsafe 状态。

```text
可信宿主请求模块入口，先取得文本和响应头
  → 解析并验证 ModuleMeta
  → 注册模块的初始化 Promise
  → 创建资源服务、平台对象和执行器
  → 加载并执行 env.js
  → 模块 ready
  → 加载 routes.js、模板和组件
```

- 宿主的发现请求是框架内部入口，不向模块代码暴露。unsafe HTML 不能先作为可执行 DOM 挂载，再检查响应头。
- 直接按 scoped 预加载模块，也要先获取带后端元信息的响应，例如 env.js；不能先原生 import，再补元信息。
- 同模块的并发加载等待同一个初始化 Promise，不能取到正在初始化的半成品后继续执行。模板加载和预加载不另建初始化分支。
- 状态为 `loading → ready / failed → disposed`。失败有明确错误，重试通过重新加载产生新代次；初始化失败不回退到根模块或普通执行器。
- 不再依赖全局 `_loadingStack` 推断当前模块。提供给 env.js 的服务明确绑定所属模块，不把真实 ModuleContextManager 交给模块脚本。
- 跨模块初始化循环直接报告依赖链；模块内 ESM 依赖的循环由选定模块加载器按其明确支持的语义处理。
- 资源缓存刷新和模块代码重新加载沿用首次确定的 unsafe 属性。代次和销毁机制只负责资源生命周期及异步回收，不承担权限变化处理。

模块自身不因父 DOM 组件的标记改变身份。同模块内天然共享策略；跨模块组件、插槽、props 和事件属于显式边界，不能通过 `$sys` 原型链、全局 `$mod` 回落或原始对象引用获得宿主能力。

## 3. 职责与依赖

按职责组织文件，不为每个概念再建一层工厂或可扩展注册体系。以下是目标归属，实际文件拆分以依赖清晰为准。

| 部分 | 唯一职责 | 必须移出的职责 |
| --- | --- | --- |
| `module.js` | 响应元信息、模块登记、初始化、代次和销毁 | URL 拼接、模板解析、执行具体 JS |
| `resource.js` | 地址解析、权限判断、请求、受控资源交付 | 执行业务 JS、创建模块状态 |
| `execution/` | 模块代码、表达式、import、任务队列及值边界 | DOM 遍历、自行拼接资源地址 |
| `execution/platform.js` | 提供原生平台或模块绑定的浏览器 API 代理，适配参数、结果与事件 | 自行实现另一套地址规则、管理业务状态 |
| `template.js` | 将 HTML/CSS/脚本解析为描述数据 | 加载时直接向 document.head 注入资源或执行脚本 |
| `compiler.js` / `compiler-attrs.js` | 把指令编译为绑定与事件操作 | 原生求值、unsafe 判断、路径规则 |
| `renderer.js` | 真实 DOM 的创建、更新和受控节点操作 | 自行执行表达式、模块发现 |
| `reactive.js` | 数据身份、依赖收集、通知和批处理 | 直接访问 window/document、安装页面监听器 |
| component / lifecycle / router | 实例、生命周期、路由行为 | 自行决定信任级别、直接 import 模块代码 |

模块装配资源服务、平台对象与执行器，下游消费已绑定模块的服务。资源服务不反向访问全局模块管理器。模板解析产物不携带已经发生的加载副作用。

## 4. 一个执行接口，两种实现

创建模块时选择执行器；编译器和生命周期不再传 unsafe 参数，也不做模式判断。

组件变量的查找规则保持统一。排除 JS 自身的局部词法变量后，框架作用域按以下顺序查找：

```text
普通模块：$data → $mod → $sys → 原生平台对象
unsafe： $data → $mod → $sys → 模块代理平台对象
```

代码只面对一个 platform，模块创建时确定其实现，组件不另走一套编译逻辑。unsafe 的最后一层是框架提供的模块 API 集合，未提供的成员不回落到原生 window。这里的“代理”描述能力接口，不要求使用 `new Proxy(window)`；执行隔离由执行器保证。

unsafe 的 `$data`、`$mod`、`$sys` 也只能包含解释器内的数据或明确提供的受控能力，不能在高优先级层挂入原生宿主对象，绕开最后一层的限制。

- 普通模块使用浏览器执行器。
- unsafe 模块使用独立 JS 引擎，优先验证 QuickJS WASM；禁止回退到浏览器执行。
- 对外只有执行、观察、赋值、调用、导入、销毁等必要操作。引擎句柄不能渗入组件和路由实现。
- setup、env.js、routes.js、生命周期、模板表达式、事件、双向绑定和动态 import 都经所属模块执行器；不能只迁移 script setup。
- `findLastAccess` 的独立 `new Function` 路径删除。双向绑定统一解析为可赋值目标，由执行器生成/执行 getter 和 setter；不支持的表达式明确报错，不再回退到捕捉“最后一次访问”的旧语义。
- JS 语法解析使用成熟解析器。删除正则剥 import、特殊字符串替换和 .min.js 名称推断；静态与动态 import 都由模块加载服务处理。
- `vhtml check` 与运行时复用语法编译入口，但 checker 只解析/编译，不执行代码。

首版优先验证同线程的 QuickJS 执行器，避免同时引入 Worker 消息协议、跨线程状态副本和异步 DOM 读写。独立 JS 堆提供能力隔离；执行中断、内存和桥接调用限额需要明确实现。此选择不等同于线程隔离，不能承诺所有宿主调用都可被 VM 中断。

QuickJS 的同步模板求值、异步 fetch、模块导入和宿主回调重入必须先用小样验证，尤其不能把 Asyncify 的异步模块加载当作可随意重入的同步 API。验证通过后锁定一种实现，不保留多套候选后端和失败降级。Worker 只有在验证结果证明必需时才进入正式方案。

- [quickjs-emscripten：显式能力注入、模块加载、Promise 与 Asyncify](https://github.com/justjake/quickjs-emscripten)
- [QuickJS：内存限制和执行中断](https://bellard.org/quickjs/quickjs.html)

## 5. 数据、响应式与浏览器能力

unsafe 的 `window === self === globalThis`，都指向解释器自己的全局对象，通过模块代理平台提供浏览器能力。按 API 保留熟悉的调用方式，底层实现不透明透传原生对象。

- `fetch`、`window.fetch`、`$mod.fetch` 是同一个模块能力。保留异步 fetch 与常用 Response 的使用方式，但不把宿主 Request/Response/Headers 实例直接交给解释器。
- `XMLHttpRequest`、`WebSocket`、`EventSource` 和 `navigator.sendBeacon` 均提供模块绑定的封装版本，不因它们是独立网络 API 就整体禁止。裸构造器与 window 下的同名构造器引用同一个封装，navigator 也是提供必要成员的受控对象。
- 定时器和 Promise 回调在模块执行器内运行，并归所属组件或模块资源回收器管理。回调、错误和异步结果同样必须经过边界。
- `$node` / `$refs` 提供范围限定的节点句柄和有限方法；`$event` 提供数据快照及受控事件操作；`$scope` 只提供任务与清理方法。它们都不是宿主对象的包装透传。
- 浏览器默认行为需同步处理的事件修饰符，如 prevent/stop，由宿主监听器在派发时执行，不依赖延迟返回的数据快照。
- 不暴露 ownerDocument/defaultView、原生 history/location、通用选择任意宿主节点的 API、任意 DOM 属性写入和原始 innerHTML 写入。
- `$bus` 默认限定本模块，unsafe 不自动读取/写入 manager.globals，也不获得广播到所有模块的入口。
- 路由用模块范围内的视图；访问真实浏览器导航由宿主服务决定，不透传原生 history 对象。

网络 API 的外形各自保留，权限和地址规则共用 resource 服务：

| API | 地址接入点 | 封装负责的行为 |
| --- | --- | --- |
| fetch | 请求创建时 | 参数、取消、响应与流数据的边界转换 |
| XMLHttpRequest | open 时解析、send 时执行 | 状态、响应类型、事件、超时和 abort 的明确支持契约 |
| WebSocket | 构造时 | ws/wss 协议映射、子协议、消息、状态和 close |
| EventSource | 构造与重新连接时 | SSE 解析、事件、Last-Event-ID、重连和 close |
| navigator.sendBeacon | 入队时 | 模块地址校验、请求体与队列限额、同步布尔返回值及发送生命周期 |

构造器返回的实例、回调里的 this、event.target/currentTarget、响应和错误均留在代理对象体系里，不能只改了 URL 就返回原生实例。原生 XHR 的 responseXML 是 Document，若支持该响应类型，必须另行提供受控表示，不能透传宿主 Document。具体支持范围在实现与测试中明确，未实现的成员不偷偷调用原生版本。[XHR 标准](https://xhr.spec.whatwg.org/)

EventSource 原生语义包含重定向和重连，因此每次实际请求都必须遵守资源策略；仅在构造时添加前缀不够。sendBeacon 保留同步布尔返回值，表示是否接收进发送队列，不改成 Promise，也不把返回 true 当作送达成功。[EventSource 标准](https://html.spec.whatwg.org/multipage/server-sent-events.html)、[Beacon 标准](https://w3c.github.io/beacon/)

底层原生 API 不能落实既定重定向策略时，通过可控制请求的传输适配实现外层 API，不在请求已经越界后才检查 responseURL。模块销毁关闭 WebSocket/EventSource、停止重连和移除回调；已接收入队的 Beacon 按明确的发送生命周期处理，只保留发送所需数据，不保留模块执行环境。

状态只存一份：unsafe 的业务状态与响应式依赖位于解释器内，宿主 renderer 接收绑定结果和有限操作。保留一套不依赖 DOM 的响应式核心，调度和诊断通过明确接口注入，不复制两套响应式算法。

数组/对象的稳定身份用模块私有句柄表达，保证 v-for 不因每次结果序列化而重建。宿主验证句柄所属模块、代次和有效性，不接受另一模块传入的节点 ID。组件销毁释放其订阅和句柄；模块销毁释放整个执行环境。

同模块组件保留既有状态共享语义。跨模块 props/事件使用明确的数据传递与能力协议，不默认共享响应式对象、函数、模块上下文或宿主 DOM。跨模块插槽按源模块执行，节点操作也必须遵守实际归属，不能借投影取得宿主权限。

## 6. 一个资源解析与访问入口

流程固定为：解析输入语义 → 得到规范地址 → 检查模块权限 → 请求 → 检查响应 → 交付结果。

- 模块地址和文件相对地址有明确 base；最终规范化、边界校验和请求实现只保留一份。
- 模板、fetch、XMLHttpRequest、WebSocket、EventSource、sendBeacon、JS、CSS、组件、路由资源均调用该入口。导航不是 fetch，但目标解析使用相同模块根与越界约束。
- 用户路径与框架内部已解析资源记录分开，不再用“看起来已经带了 scoped”猜测是否添加前缀。
- unsafe 的 `@`、异常编码、反斜杠歧义、目录穿越和非获准协议在这里处理；不得由不同调用点各自修补或静默改写。
- unsafe 请求不自动跟随重定向，防止初始地址在模块内而后续请求越界。请求方法、凭证、请求头和选项由能力契约校验，调用方不能覆盖限制。
- 错误包含模块、资源地址、调用位置和拒绝原因，不使用只 warn 然后跳过的行为。

原生元素的自动加载也是网络出口。对 unsafe 不能仅给 img/link 的 URL 加前缀就放行，因为重定向、样式嵌套依赖和主动内容仍可能越界。

- 资源服务获取获准资源，再交付受控的内容/句柄；例如通过框架创建的对象 URL 提供允许的被动二进制资源，并管理释放。
- HTML、CSS 和 SVG 等能包含执行或嵌套资源的格式必须先解析和校验，不能仅因转成 blob 就当作安全内容。未覆盖的主动格式明确拒绝。
- 静态模板、动态属性和 v-html 使用同一个受控渲染入口；在插入真实 DOM 前完成检查，不依靠插入后的 MutationObserver 补救。
- 禁止原生 on* 事件属性、任意 script/iframe/object/embed/base/meta refresh 和表单/链接绕过资源与导航服务的默认行为。框架的 @event 指令仍正常工作。
- CSS 的 url()/@import/font 等依赖经解析器统一处理，不能用正则替换代替资源边界。
- 不新造完整虚拟 DOM；仍由 renderer 对真实 DOM 做定向更新。有限节点接口和模板描述数据不承担浏览器对象模型的全量模拟。

## 7. 旧实现的删除清单

以下内容在替换各职责时直接删除，不保留兼容导出：

- 组件 `unsafe` 属性的读取与向后代传播；checker 中旧组件 unsafe 指令定义。
- `instance.unsafe`、`runtime.__unsafe`、`options.unsafe` 和 load/parse/run 链上的 unsafe 布尔参数。
- `$mod.restrictedFetch`，以及运行时把裸 fetch 特判为另一函数的逻辑。
- 原 sandbox.js 的 safeFunction/safeView 构造器黑名单与“防误触沙箱”执行分支。普通执行器如果需要作用域解析，只保留这一明确职责，不再承担安全承诺。
- unsafe 下删除 import、禁用 vsrc/:vsrc、跳过外部脚本的散落分支；由资源归属与执行器统一决定允许的加载。
- `renderer.findLastAccess` 的原生求值旁路及其旧绑定结果格式。
- loader/module/imports/compiler-attrs/router 中重复的资源前缀、@ 处理和路径归一化代码；路由自身的匹配算法保留。
- loader 中解析时加载样式、链接、脚本的隐式副作用；替换成资源服务和 renderer 的显式操作。
- 暴露给模块的全局 manager、依靠全局栈推断调用者，以及身份/权限参与普通配置 merge 的路径。
- 跟上述旧路径绑定的测试、示例和当前设计说明，按新契约一次改写。历史 changelog 保留历史记录，不能再作为现行用法。

## 8. 实施顺序与完成标准

### 阶段 0：验证执行核心

用最小模块验证独立引擎的 setup → 响应式绑定 → 事件更新 → 网络 API 代理 → 静态/动态 import → dispose。覆盖 fetch、XHR、WebSocket、EventSource、sendBeacon 的代表用法、回调归属与回收；测同步绑定、列表身份、异步加载期间的事件处理、异常传播、中断及句柄释放。记录包体、启动耗时和绑定开销，再锁定执行器方案。验证代码不成为永久兼容层。

### 阶段 1：建立模块与资源边界

实现后端元信息、模块初始化 Promise、资源地址契约、权限和销毁。整合重复 URL 实现；删除组件级安全标记及状态。新 unsafe 执行器未就绪时明确拒绝挂载，不允许暂借普通执行器运行。

### 阶段 2：切换所有代码执行入口

接入普通/隔离执行器，迁移 env/routes/组件脚本/表达式/import/双向绑定，拆出无 DOM 的响应式核心，建立值与事件边界。删除旧 sandbox.js 和独立原生求值旁路。

### 阶段 3：收口渲染、资源与跨模块组合

模板解析去副作用，统一动态/静态 DOM 写入与资源交付；收口节点、路由、事件总线、props 和插槽。模块销毁统一取消可取消的请求、任务、订阅，关闭长连接并停止重连，回收对象 URL、节点句柄和引擎；已接收的 Beacon 遵守上述发送生命周期。

### 阶段 4：回归与清理

修改仓库内调用方、checker、构建产物和现行文档。旧测试按契约改写，不为旧 API 继续能用而保留代码。不在中间阶段发布半套沙箱。

验收围绕实际行为：

1. 标记来源：只在模块首次登记时读取后端 unsafe 头；执行 env.js 前已生效；前端赋值和后代组件不能改变策略，后续加载沿用初始化结果。
2. 加载一致性：首次、并发、缓存命中、预加载、刷新、失败和销毁后迟到响应都遵守同一模块状态机；不设计标记变化或冲突处理流程。
3. 路径：五类网络 API、模板/CSS/import/路由的前缀与边界一致；@、编码穿越、Request/URL 输入、协议变体、重定向和自动重连不能越界。
4. 执行：this、构造器、原型、动态 import、定时器、双向绑定、节点/事件引用都无法取得宿主能力；普通模块保持正常浏览器使用能力。
5. 渲染：真实浏览器记录网络请求，验证 img/CSS/font/v-html/链接/表单/iframe/SVG 等入口；只运行 happy-dom 单测不算网络隔离通过。
6. 行为：生命周期、v-if/v-for 身份、props、双向绑定、路由缓存、模块内共享状态及跨模块组合符合明确契约。
7. 回收与限额：循环代码和耗尽内存可被终止；模块销毁后用户任务不再运行，可取消请求、长连接、重连、订阅、对象 URL 和引擎句柄不残留；已入队 Beacon 不持有执行环境。

验收时还要静态检索所有宿主 Function/eval/import/fetch 和自动资源插入点：每个点必须有明确职责归属，不能遗留“方便调用”的旁路。
