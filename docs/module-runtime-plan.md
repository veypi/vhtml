# 模块运行时设计

当前实现与约定，2026-10-02；“架构精简审查”记录本次实施范围与保留项。完整 API 范围、限制与测试方法见 [模块沙箱](module-sandbox.md)。发布前直接替换旧实现，不保留组件 unsafe、旧沙箱或兼容分支。

## 固定边界

- unsafe 是模块属性，仅从后端首次响应的 `vhtml-unsafe` 头判定，按头是否存在判断。unsafe 必须同时有非根 `vhtml-scoped`。
- 首次元信息不可变，清缓存不重新判定。后端标记变化由后端负责，前端不增加检测、切换或调和状态机。
- 变量查找顺序统一为 `$data → $mod → $sys → 平台对象`。普通模块使用原生执行器；unsafe 使用独立 QuickJS WASM 引擎及框架提供的能力。
- 隔离引擎失败即失败，不回退到原生执行。构造器、原型链、eval、Function、异步回调和 import 都属于模块引擎。
- 保留共享真实 DOM 和 CSS，不使用 Shadow DOM、iframe 或另一棵虚拟 DOM。JS 不能获得原生浏览器对象；CSS 继承、选择器和跨根原生关联不作为严格隔离边界。

## 权责

| 部分 | 唯一职责 |
| --- | --- |
| `module.js` / `execution/context.js` | 模块发现、首次元信息、初始化与私有记录 |
| `resource.js` | 地址语义、模块前缀、越界检查、传输与请求租约 |
| `execution/module-executor.js` | 装配模块能力、组件执行上下文和模块终止 |
| `execution/isolated.js` | VM、值转换、执行预算、异步任务和句柄清理时机 |
| `execution/network*.js` | Web API 外形、网络事件和流的复制适配；地址规则交给资源服务 |
| `execution/render-policy.js` / `dom-schema.js` | 模板与动态 DOM 的规则、资源转换、组件归属和异步写入 |
| `execution/dom*.js` / `canvas*.js` / `webgl*.js` | 受控节点与绘图操作、事件快照；不透传原生对象 |
| loader / compiler / component / router | 模板描述、绑定、组件生命周期与路由，消费所属模块的执行器 |
| `reactive-core.js` | 原生与隔离执行器共享的响应式算法 |

不另外增加策略管理器、平台插件层、模式切换器或兼容适配器。一个资源解析入口，一套渲染规则，一条模块终止路径。

## 框架主流程

- `resource.js` 生成规范绝对 URL。模板读取、缓存键、`scopeOf` 和缓存失效共用资源身份；导航路径由 router 处理，不复用资源前缀规则。
- 普通执行器、隔离执行器和 CLI 共用 AST 源码处理。两个引擎内运行同一个作用域查找函数；调用局部变量位于 `$data/$mod/$sys` 之后、平台之前。
- `env.js` 获得绑定所属模块的 manager 接口。并发初始化、相对模块加载和别名登记不依赖全局“当前模块”；执行诊断随 runtime 传递。
- 模块登记只保留一份记录，包含初始化 Promise、别名、资源与执行器。清缓存移除记录，旧初始化通过记录身份判定失效；迟到的 env 不能登记别名、全局能力或加载子模块，也不能删除新模块记录。模块发现复用 env 存在性结果并取消探测响应体，普通模块不重复探测。
- 每个 unsafe 组件只有一个持久 VM 执行上下文。列表行和临时作用域在调用时传入当前数据，移除行不留下等待组件销毁的 VM 上下文；setup 阶段状态仍归组件所有。
- loader 先获取并检查来源，parser 只提取描述符，随后由资源服务和模块执行器准备脚本、样式等依赖。解析本身不执行 head 脚本或注入样式。
- `parseRef(vsrc, dom, data, runtime, options)` 仅接受统一 options，包含 `target`、`single`、`keepOnDetach`。`parseRaw` 通过同一挂载流程完成。两者返回挂载完成的 Promise，失败 reject；组件展示错误，路由决定保留当前页、错误跳转或首次错误页。
- 双向绑定只接受静态属性路径，包括数字下标和转义字符串键。删除执行任意表达式猜测赋值位置的旧分支；动态索引用显式事件赋值。
- 每个待构建页面持有目标路由状态。构建不修改视图 `current`，提交时更新当前页、页面及 layout 的状态；取消无需回滚共享状态。
- unsafe 路由回调只接收公开路由数据快照；matcher 等宿主对象不跨边界。守卫的 `next` 在 VM 内创建，回调完成后由宿主执行重定向；文件与内联路由共用入口。

## 网络与加载

`fetch('/api/xxx')`、XHR、WebSocket、EventSource、Beacon、脚本 import 与框架识别的资源地址都经模块资源服务。模块根为 `/modules/demo` 时，`/api/xxx` 对应 `/modules/demo/api/xxx`。

- unsafe 禁止 `@`、外域、模块外路径、协议相对地址、歧义编码和未提供的协议。
- import 相对路径基于源文件，根路径基于模块。URL/Request 输入不会跳过校验。
- HTTP 禁止重定向，SSE 经受控 fetch 实现。JS 侧只获得引擎内的 Response、事件及复制数据。
- 空响应收到头后释放租约；其他响应在读取结束、取消或不再被引用时回收。读取器自身可以维持响应存活。
- 接收过的 Beacon 可在模块销毁后完成，只保留发送数据，不保留执行环境。
- 第三方库从模块内加载，在模块 window 中共享；不能直接使用 CDN 或 `@` 访问全局库。

## DOM 与写入

`$node`、`$refs`、事件目标、Canvas 和 WebGL 都是引擎内的有限接口。native DOM/Window/Document/GPU 对象留在宿主桥接闭包中。查询、关系与操作检查模块归属。

模板先经无浏览器副作用的解析器检查；HTML 元素规则与程序化创建共用。script/style/head stylesheet 由加载器消费为代码或样式，不作为动态可创建元素。原生 on* 属性和主动嵌入元素不开放。

静态资源绑定、动态属性和 DOM style 方法使用同一个 RenderPolicy 写入记录：属性代次保证新值优先，组件归属阻止销毁后的异步写回。节点重新接管会使之前的写入失效。

原生和 unsafe 绑定共用值规范化、样式 diff 与表单属性写入语义。样式对象在依赖收集时生成快照，原地修改和删除字段都能触发更新，静态样式保留；RenderPolicy 只在写入边界增加检查与资源转换。

显式资源 URL 经受控请求转换为 Blob。组件 CSS 作用域继续保留，但不承诺共享 CSS 的继承值、宿主选择器或原生 ID/表单关联被完全隔离。这也意味着封装 API 的网络限制不能等同于整个浏览器的被动网络隔离。

## 生命周期与回收

组件清理先运行库自己的 dispose/destroy，再撤销其 DOM 能力、监听器和 GPU 资源。模块退休等待仍在使用它的组件结束。模块正常销毁、初始化失败和 VM 执行超限最终进入同一幂等终止流程。

ModuleExecutor 持有模块资源并负责终止。VM 只报告致命错误、释放自身状态，不反向触发模块 dispose 回调；能力装配失败也由同一入口清理已安装的部分。一项清理失败不阻断其他资源释放。

JS 仍引用的节点、响应及读取器保持有效。已挂载 DOM 代理保留对象身份及库附加数据；临时对象使用弱句柄，在 VM 任务结束后回收，避免把历史分配数变成终生额度。组件关闭立即使其异步写入失效，模块关闭释放全部剩余资源。

时间与内存预算限制模块 JS；同线程宿主 DOM 调用和 GPU 工作不承诺硬实时隔离。支持范围保持显式，未实现的浏览器能力不偷偷调用原生版本。

## 架构精简审查

本次完成第 1、2、4 项；第 3 项保留现状。精简聚焦同一事实的多份状态、重复执行入口和无调用方分支，不以文件数、类数或行数作为目标。

### 1. 模板缓存与失效判断（已完成）

[TemplateLoader](../src/loader.js) 使用单个 Map，每个规范 URL 对应一条 `{ ready, descriptor }` 记录。记录先登记再启动异步工作；并发调用共用 ready，`scopeOf` 只读就绪描述符。删除原来的 `cache.templates`、`cache.pending` 和全局模板 `_epoch`。

`clearScoped` 仅删除命中记录，`clear` 删除全部记录。加载过程在异步恢复后、进入后续依赖准备及返回前检查记录身份；失效加载 reject，失败只删除自身记录，旧任务不能覆盖或删除新任务。修复清 A 误伤在途 B，以及准备依赖期间清理仍返回旧描述符、继续运行后续 head 脚本的问题。`keepLive` 继续保留存活模块、别名和样式。

[缓存回归](../test/clear_scoped.test.js) 通过实际加载和请求次数验证前缀/域名边界、同 URL 并发去重、清 A 不影响 B、旧请求成功或失败均不污染替代记录、三种清理方式下的依赖竞态、失败重试及 `scopeOf`。不再手工填充双 Map 或断言 `_epoch`。原生 ESM 的 `importEpoch` 负责浏览器模块缓存穿透，继续保留；没有新增通用缓存管理器。

### 2. 原生 import 执行路径（已完成）

[imports.js](../src/imports.js) 中的 `importNative(url)` 统一执行已解析 URL 的原生 import、缓存穿透和 10 秒超时。[NativeExecutor](../src/execution/native.js) 的 env/routes 和 setup 静态/动态 import 共用这一入口，AST 处理仍由 `source.js` 承担。

地址约定保持原样：setup 相对路径基于源文件，env/routes 基于模块；普通 setup import 补全 `.js`，unsafe 仍要求完整文件名。[原生 import 回归](../test/native-imports.test.js) 使用真实 ESM 夹具验证相对路径、模块根路径、查询参数、并发命名空间身份、缓存穿透及各入口的错误传播。未引入加载器基类或策略选项。

### 3. 隐式原生兜底（本次不调整）

[resourcesFor](../src/resource.js) 的临时普通模块资源服务、[Run / AsyncRun](../src/sandbox.js) 的原生回落，以及 [RouterView.loadRoutes](../src/router/view.js) 的执行器兜底保持现状。如后续收口，应先核对模块发现前的宿主请求、根挂载和 `parseRaw` / `parseDom` 调用约定，再要求内部调用使用已登记模块；不新增注册中心或空的执行器接口。

### 4. 无用接口与测试开关（已完成）

删除无调用方的 `mergeModulePatch`、仅测试使用的 `createScopeProxy` 旧别名，以及 `createModule` 的 `loadEnv` 参数和分支。作用域测试直接使用 `nativeScope`；模块测试经 `getModule` 和 env 404 夹具走正常初始化路径。保留生产需要的 env 存在性结果与探测去重，不增加兼容包装。

### 保留的必要复杂度与停止条件

- 首次元信息登记与可失效的模块记录寿命不同，不能为了“一张表”一起清除；清缓存不得重新判定 unsafe。
- ModuleExecutor 的能力装配和 IsolatedExecutor 的 VM 执行职责不同；宿主适配与 realm 内 Web API 也不能合成透传原生对象的桥接。小型 WeakMap 登记文件有明确的私有边界，不因文件短而强行合并。
- 组件拥有者、模块退休/关闭、请求租约、写入代次和弱句柄分别解决存活实例、取消及迟到结果问题。它们不是同一种状态，不引入统一生命周期状态机来替代。
- 保留无浏览器副作用的 HTML 预检、DOM 所有权检查与共享值规范化。不同引擎分别缓存编译结果是必要的，不能共享原生 Function 或 VM 句柄。
- 网络、DOM、Canvas、WebGL 的范围以当前文档和真实库用例为限；本次不继续扩展成完整浏览器兼容层，也不增加平台插件、模式切换、通用桥接协议或代码生成框架。

第 1、2、4 项到此收口，不继续扩展抽象或浏览器能力。新增竞态测试在修改前复现失败，修改后通过。本次验证：`npm test` 324 项通过、`npm run build` 成功、`node scripts/check-sandbox-build.mjs` 压缩产物挂载通过，`git diff --check` 无错误。本次未重跑真实浏览器夹具。
